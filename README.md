# 지원처 맞춤 포트폴리오 빌더

채용 공고를 붙여넣으면 **내 이력 중 무엇을 앞에 둘지** 계산해 주고,
그대로 웹페이지(HTML)와 발표자료(PPTX)로 뽑아 주는 Streamlit 앱입니다.

이력은 한 번만 입력하면 됩니다. 회사를 새로 지원할 때마다 공고문만 갈아 끼우면
순서 · 강조 문구 · 자기소개가 그 공고에 맞게 다시 짜입니다. 원본 이력은 그대로 두고요.

코드를 고칠 필요 없이 화면에서 전부 입력합니다.

## 바로 써보기

`시작하기 → 예시 데이터 불러오기` 를 누르면 가상 인물의 데이터로 기능을 먼저 볼 수 있습니다.

## 로컬에서 실행

```bash
pip install -r requirements.txt
```

```bash
streamlit run app.py
```

브라우저에서 `http://localhost:8501` 이 열립니다.

## 쓰는 순서

| 탭 | 하는 일 |
|---|---|
| **시작하기** | JSON 불러오기 · 예시 데이터 · 빈 문서로 시작 · 저장 |
| **내 정보** | 인적사항, 사진, 학력, 어학, 역량, 자격, 수상, 활동, 자유 섹션 |
| **경력 · 프로젝트** | 회사 경력과 프로젝트를 배경 → 실행 → 성과로 입력 |
| **공고 분석** | 공고문을 붙여넣고 충족률 · 보완 포인트 확인 |
| **추천 수정안** | 헤드라인 · 자기소개 · 순서 · 강조 문구 추천을 골라서 적용 |
| **미리보기 · 다운로드** | HTML · PPTX · JSON 내려받기 |

**내 정보 / 경력 · 프로젝트** 는 한 번만 채우면 됩니다.
회사를 새로 지원할 때는 사이드바에서 `+ 새 지원처` 를 누르고
**공고 분석 → 추천 수정안** 만 다시 하면 됩니다.

## 추천은 어떻게 만들어지나

`core/tags.py` 의 사전이 공고문 표현을 역량 태그로 바꿉니다.
예: "데이터 기반", "지표 관리" → `데이터분석`, `지표관리`

그 태그로 두 가지를 계산합니다.

1. **충족률** — 내 이력에 붙은 태그와 대조해 비율을 내고, 못 채운 항목마다
   *내 데이터 안에서 가장 가까운 근거*를 찾아 보완 방법을 알려줍니다.
2. **추천 문장** — 헤드라인 · 한 줄 소개 · 자기소개 · 강조 문구를
   **입력된 내 데이터만 조합해서** 만듭니다. 없는 경력이 지어내지지 않습니다.

받침에 따라 을/를 · 과/와 · 으로/로를 고르고, 헤드라인을 두 줄로 나눌 때는
연결어미 뒤를 우선해서 끊습니다. 기계가 쓴 티가 덜 나도록 한 장치입니다.

사전에 없는 업계 용어를 놓치지 않도록, 공고에는 자주 나오는데 내 포트폴리오에는
한 번도 안 나오는 단어도 따로 뽑아 보여줍니다. 이건 사전과 무관하게 어떤 분야에서도 동작합니다.

새 업계를 다룬다면 `core/tags.py` 의 `TAGS` 에 항목을 추가하세요.

```python
"태그이름": ("화면에 보일 이름", "분류", ["공고문에 나올 표현", "동의어"]),
```

## 성과 수치 숨기기

대행사에서 다룬 광고주 성과처럼 대외비일 수 있는 숫자를 위해,
프로젝트마다 **숫자 없는 문장**을 함께 적어 둘 수 있습니다
(`경력 · 프로젝트 → 🔒 수치 숨김용 문장`).

`추천 수정안 → 구성 · 순서 → 구체적인 수치 숨기기` 를 켜면 그 문장으로 바뀝니다.
원본 숫자는 지워지지 않으므로 지원처마다 켜고 끌 수 있습니다.

## 결과물

- **HTML** — 이미지까지 파일 하나에 들어갑니다. 메일 첨부 · 웹 업로드 모두 가능.
  PDF 가 필요하면 브라우저에서 열고 `Ctrl+P` → PDF로 저장 (인쇄용 스타일 적용됨).
- **PPTX** — 16:9. 모든 요소가 일반 도형 · 텍스트라 PowerPoint 에서 자유롭게 재편집됩니다.
- **JSON** — 다음에 이어서 작업할 데이터.

강조 색은 지원처마다 바꿀 수 있고, 웹페이지와 PPT 에 함께 반영됩니다.

## 데이터는 어디에 저장되나

**입력한 내용은 브라우저 세션에만 있고 서버에 저장되지 않습니다.**
창을 닫으면 사라지므로 `JSON 내보내기`로 내려받아 보관하세요.
다음에 그 파일을 올리면 이어서 작업할 수 있습니다.

이미지는 data URI 로 JSON 안에 들어갑니다. **JSON 파일 하나만 옮기면**
다른 컴퓨터에서도 사진까지 그대로 복원됩니다.

### 내 PC 에서 혼자 쓸 때

`data/.local` 이라는 빈 파일을 만들어 두면 **로컬 모드**가 켜집니다.

```bash
type nul > data\.local     # Windows
touch data/.local          # macOS · Linux
```

로컬 모드에서는 `시작하기 → 이 컴퓨터에 저장` 버튼이 활성화되고,
저장한 내용을 다음 실행 때 자동으로 불러옵니다.

`data/.local` 과 `data/my_portfolio.json` 은 `.gitignore` 에 등록되어 있어
저장소에 올라가지 않습니다. 그래서 **배포본에서는 로컬 모드가 자동으로 꺼집니다.**
여러 사람이 쓰는 주소에서 서버 파일에 저장하면 다음 접속자에게 남의 이력이
보이기 때문에, 일부러 이렇게 막아 두었습니다.

## 배포하기 (Streamlit Community Cloud)

1. 이 저장소를 본인 GitHub 계정으로 올립니다 (public / private 둘 다 가능).
2. [share.streamlit.io](https://share.streamlit.io) 에 GitHub 계정으로 로그인합니다.
3. `Create app` → 저장소를 고르고 **Main file path 를 `app.py`** 로 지정합니다.
4. `Deploy` 를 누르면 `<이름>.streamlit.app` 주소가 생깁니다.

`requirements.txt` 가 저장소 루트에 있으므로 별도 설정은 필요 없습니다.
코드를 수정해 push 하면 자동으로 다시 배포됩니다.

> **올리기 전에 확인하세요.** 개인 이력이 담긴 `data/my_portfolio.json` 이
> 저장소에 포함되지 않았는지 `git status` 로 한 번 보세요. 무료 등급은 메모리가
> 넉넉하지 않으므로, 사진은 앱이 자동으로 줄여서 저장합니다(가로세로 최대 1400px).

## 파일 구성

```
app.py                  진입점 · 사이드바 · 페이지 네비게이션
core/tags.py            역량 태그 사전, 공고 키워드 추출
core/schema.py          데이터 구조, 렌더링용 뷰 생성
core/reco.py            공고 분석 · 추천 문장 생성 (한국어 조사 처리 포함)
core/render.py          HTML 포트폴리오 생성
core/deck.py            PPTX 생성 (python-pptx)
core/io_utils.py        이미지 · JSON 입출력, 로컬 모드 판별
views/                  화면 6개
static/portfolio.css    결과물 스타일 (--accent 만 바꾸면 색이 전부 따라옵니다)
data/demo.json          예시 데이터 (가상 인물)
```

## 데이터 구조

문서 하나(JSON)에 전부 들어 있습니다.

```
doc
├── base          내 이력 원본 — 사실 데이터. 지원처를 늘려도 그대로.
│   ├── person, education, languages, skills, certificates, awards, activities
│   ├── experience[]   경력
│   ├── projects[]     프로젝트
│   └── custom         자유 섹션 (질문/답변)
└── targets       지원처별 설정 — 같은 사실을 어떻게 보여줄지
    └── <id>
        ├── company, position, jd_text …
        ├── hero_title, hero_tagline, intro, metrics
        ├── project_order / project_visible / project_emphasis
        ├── hide_numbers   구체적 수치 숨김 여부
        └── overrides      문장별 덮어쓰기
```
