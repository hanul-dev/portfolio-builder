# Tailor · 공고에 맞춰 다시 쓰는 포트폴리오

**이력서 파일과 채용 공고만 넣으면 포트폴리오가 만들어집니다.**

이력서(PDF · Word)를 올리면 경력 · 프로젝트 · 학력을 자동으로 나눠 읽고,
공고문에서 요구 역량을 뽑아 **내 이력 중 무엇을 앞에 둘지** 계산한 다음,
웹페이지(HTML)와 발표자료(PPTX)로 뽑아 줍니다.

회사를 새로 지원할 때는 공고문만 갈아 끼우면 순서 · 강조 문구 · 자기소개가
그 공고에 맞게 다시 짜입니다. 원본 이력은 그대로 두고요.

없는 경력을 지어내지 않습니다. 모든 문장은 **입력된 본인 데이터만 조합해서** 만듭니다.

## 바로 써보기

`불러오기 · 저장 → 예시 데이터 불러오기` 를 누르면 가상 인물의 데이터로 기능을 먼저 볼 수 있습니다.

## 로컬에서 실행

```bash
pip install -r requirements.txt
```

```bash
streamlit run app.py
```

브라우저에서 `http://localhost:8501` 이 열립니다.

## 쓰는 순서

| 탭 | 하는 일 |
|---|---|
| **자동 만들기** | 공고 + 이력서 파일 → 포트폴리오 한 번에. 여기서 끝내도 결과물이 나옵니다 |
| **내 정보** | 인적사항, 사진, 학력, 어학, 역량, 자격, 수상, 활동, 자유 섹션 |
| **경력 · 프로젝트** | 회사 경력과 프로젝트를 배경 → 실행 → 성과로 다듬기 |
| **공고 분석** | 공고문을 넣고 충족률 · 보완 포인트 확인 |
| **추천 수정안** | 헤드라인 · 자기소개 · 순서 · 강조 문구 후보를 골라서 적용 |
| **미리보기 · 다운로드** | HTML · PPTX · JSON 내려받기 |
| **불러오기 · 저장** | JSON 불러오기 · 예시 데이터 · 빈 문서로 시작 |

**자동 만들기** 한 번이면 초안이 나옵니다. 나머지 탭은 다듬을 때 씁니다.
회사를 새로 지원할 때는 사이드바에서 `+ 새 지원처` 를 누르고
**공고 분석 → 추천 수정안** 만 다시 하면 됩니다. 이력 원본은 건드리지 않습니다.

## 이력서 자동 읽기

PDF 와 Word(.docx) 를 읽습니다. 한글(.hwp) 은 PDF 로 저장해서 올리거나,
**파일 대신 내용 붙여넣기** 를 쓰면 됩니다.

채용 사이트에서 내려받은 이력서처럼 `기간 (재직기간) 고용형태 직무` 와
`[프로젝트명]` · `[담당 역할 및 실행]` 같은 라벨이 있는 양식은 정확하게 읽습니다.
자유 형식이면 섹션 제목과 날짜만으로 어림잡아 나누므로 정확도가 떨어집니다.

**규칙으로 읽는 방식이라 완벽하지 않습니다.** 그래서 만들기 전에
`이렇게 읽었습니다` 화면에서 무엇을 몇 개 읽었는지 보여 주고, 섹션으로 나누지 못한 글도
버리지 않고 남겨 둡니다. 결과는 **내 정보** · **경력 · 프로젝트** 에서 고칠 수 있습니다.

> 올린 파일은 메모리에서 처리되고 서버에 저장되지 않습니다.

## 공고 링크

링크를 넣고 `링크에서 가져오기` 를 누르면 본문을 가져옵니다.
네 가지 방법을 차례로 시도해 가장 공고다운 결과를 고릅니다 — JobPosting 구조화 데이터,
페이지에 박힌 JSON(__NEXT_DATA__ 등), HTML 본문, og:description.

실제로 여러 사이트에 넣어 본 결과입니다.

| 사이트 | 결과 |
|---|---|
| 원티드 | 성공 (3,700자, 담당업무·자격요건 구간까지 인식) |
| greenhouse · lever 등 외국 ATS | 성공 (7,800자) |
| 사람인 | 실패 — 본문이 HTML 에 없고, 이미지로만 된 공고도 많음 |
| 잡코리아 | 부분 성공 — 메뉴만 긁히는 경우가 있어 경고를 띄움 |
| 회사 자체 채용페이지 | 사이트마다 다름 |

**가져온 글이 짧으면 "메뉴만 긁어왔을 수 있다" 고 경고합니다.** 조용히 통과시키면
사용자가 잘못된 분석을 믿게 되기 때문입니다. 확실한 방법은 여전히 붙여넣기입니다.

## 공고 분석

공고문에서 `담당업무` · `자격요건` · `우대사항` 같은 제목을 찾아 구간을 나눕니다.
같은 요구사항이라도 **필수와 우대는 무게가 다르기 때문**입니다.

| 구간 | 가중치 |
|---|---|
| 🔴 자격요건 (필수) | 2.0 |
| 🔵 담당업무 | 1.5 |
| ⚪ 우대사항 | 1.0 |

충족률은 이 가중치로 계산합니다. 제목을 못 찾으면 전체를 필수로 봅니다.

### 필수 능력 점검

요구사항마다 충족 여부와 **그것을 증명하는 내 항목**을 함께 보여줍니다.

```
✅ MMORPG · RPG 이해도    프로젝트「오픈월드 RPG 브랜드 콜라보 마케팅 기획」
❌ 콘텐츠 기획 · 제작       가장 가까운 근거는 경력 「…」입니다. 이 항목의 설명에…
```

### 들어가야 할 키워드

공고가 쓰는 표현 중 내 포트폴리오에 없는 것을 뽑습니다.
사전에 잡힌 것은 **역량**, 그 밖의 말은 그 회사가 쓰는 **용어**로 구분합니다.

용어 쪽은 사전과 무관하게 동작하므로 어떤 업계든 씁니다. 예를 들어 물류 공고를 넣으면
`WMS` · `SAP` · `콜드체인` · `선입선출` 처럼 그 분야의 핵심어가 그대로 나옵니다.
조사가 붙은 토막('높으신', '맡은')이 섞이지 않도록 걸러 냅니다.

> 없는 경험을 지어내라는 뜻이 아닙니다. **실제로 해본 일을 그 회사가 쓰는 단어로
> 바꿔 쓰라는** 목록입니다.

## 추천은 어떻게 만들어지나

`core/tags.py` 의 사전이 공고문 표현을 역량 태그로 바꿉니다.
예: "데이터 기반", "지표 관리" → `데이터분석`, `지표관리`

그 태그로 두 가지를 계산합니다.

1. **충족률** — 내 이력에 붙은 태그와 대조하고, 못 채운 항목마다
   *내 데이터 안에서 가장 가까운 근거*를 찾아 보완 방법을 알려줍니다.
   체크리스트는 필수 → 담당업무 → 우대 순으로 정렬됩니다.
2. **추천 문장** — 헤드라인 · 한 줄 소개 · 자기소개 · 강조 문구를
   **입력된 내 데이터만 조합해서** 만듭니다. 없는 경력이 지어내지지 않습니다.

받침에 따라 을/를 · 과/와 · 으로/로를 고르고, 헤드라인을 두 줄로 나눌 때는
연결어미 뒤를 우선해서 끊습니다. 기계가 쓴 티가 덜 나도록 한 장치입니다.

사전에 없는 업계 용어를 놓치지 않도록, 공고에는 자주 나오는데 내 포트폴리오에는
한 번도 안 나오는 단어도 따로 뽑아 보여줍니다. 이건 사전과 무관하게 어떤 분야에서도 동작합니다.

새 업계를 다룬다면 `core/tags.py` 의 `TAGS` 에 항목을 추가하세요.

```python
"태그이름": ("화면에 보일 이름", "분류", ["공고문에 나올 표현", "동의어"]),
```

## 성과 수치 숨기기

대행사에서 다룬 광고주 성과처럼 대외비일 수 있는 숫자를 위해,
프로젝트마다 **숫자 없는 문장**을 함께 적어 둘 수 있습니다
(`경력 · 프로젝트 → 🔒 수치 숨김용 문장`).

`추천 수정안 → 구성 · 순서 → 구체적인 수치 숨기기` 를 켜면 그 문장으로 바뀝니다.
원본 숫자는 지워지지 않으므로 지원처마다 켜고 끌 수 있습니다.

## 결과물

- **HTML** — 이미지까지 파일 하나에 들어갑니다. 메일 첨부 · 웹 업로드 모두 가능.
  PDF 가 필요하면 브라우저에서 열고 `Ctrl+P` → PDF로 저장 (인쇄용 스타일 적용됨).
- **PPTX** — 16:9. 모든 요소가 일반 도형 · 텍스트라 PowerPoint 에서 자유롭게 재편집됩니다.
- **JSON** — 다음에 이어서 작업할 데이터.

강조 색은 지원처마다 바꿀 수 있고, 웹페이지와 PPT 에 함께 반영됩니다.

## 데이터는 어디에 저장되나

**접속한 사람의 브라우저 안에만 저장됩니다.** 서버에는 남지 않습니다.

작업하는 동안 자동으로 저장되고, 다음에 같은 브라우저로 들어오면 그대로 이어집니다.
로그인도, 계정도 필요 없습니다.

- 브라우저가 다르면(다른 PC · 다른 브라우저 · 시크릿창) 서로 아무것도 보이지 않습니다.
- 같은 주소에 여러 사람이 접속해도 데이터가 섞이지 않습니다.
- 저장 위치는 브라우저 localStorage 이며, 보통 **5MB** 한도가 있습니다.
  사진을 많이 넣어 넘칠 것 같으면 자동 저장을 건너뛰고 안내합니다.

사이드바에서 자동 저장을 끌 수 있고, `불러오기 · 저장` 탭에서 수동 저장과
**브라우저 저장 내용 지우기**(공용 PC 를 썼을 때)를 할 수 있습니다.

브라우저를 바꾸거나 백업하려면 `JSON 내보내기`를 쓰세요. 이미지는 data URI 로
JSON 안에 들어가므로 **파일 하나만 옮기면** 다른 컴퓨터에서도 사진까지 복원됩니다.

### 내 PC 에서 혼자 쓸 때 (선택)

`data/.local` 이라는 빈 파일을 만들어 두면 브라우저 저장에 더해
**서버 파일 저장**도 함께 켜집니다.

```bash
type nul > data\.local     # Windows
touch data/.local          # macOS · Linux
```

이때만 `data/my_portfolio.json` 을 읽고 쓰며, 앱을 켤 때 자동으로 불러옵니다.

`data/.local` 과 `data/my_portfolio.json` 은 `.gitignore` 에 등록되어 있어
저장소에 올라가지 않습니다. 그래서 **배포본에서는 파일 저장이 자동으로 꺼집니다.**
여러 사람이 쓰는 주소에서 서버 파일 하나를 공유하면 다음 접속자에게 남의 이력이
보이기 때문에, 일부러 이렇게 막아 두었습니다.

## 배포하기 (Streamlit Community Cloud)

1. 이 저장소를 본인 GitHub 계정으로 올립니다 (public / private 둘 다 가능).
2. [share.streamlit.io](https://share.streamlit.io) 에 GitHub 계정으로 로그인합니다.
3. `Create app` → 저장소를 고르고 **Main file path 를 `app.py`** 로 지정합니다.
4. `Deploy` 를 누르면 `<이름>.streamlit.app` 주소가 생깁니다.

`requirements.txt` 가 저장소 루트에 있으므로 별도 설정은 필요 없습니다.
코드를 수정해 push 하면 자동으로 다시 배포됩니다.

> **올리기 전에 확인하세요.** 개인 이력이 담긴 `data/my_portfolio.json` 이
> 저장소에 포함되지 않았는지 `git status` 로 한 번 보세요. 무료 등급은 메모리가
> 넉넉하지 않으므로, 사진은 앱이 자동으로 줄여서 저장합니다(가로세로 최대 1400px).

## 비밀번호 잠금

배포한 주소는 링크를 아는 사람 누구나 들어올 수 있습니다.
초대한 사람만 쓰게 하려면 비밀번호를 걸어 두세요.

**Streamlit Cloud → Manage app → Settings → Secrets** 에 넣습니다.

```toml
app_password = "정한_비밀번호"
```

비밀번호를 그대로 두기 싫으면 SHA-256 해시를 대신 넣어도 됩니다.

```toml
app_password_sha256 = "해시값"
```

해시는 이렇게 만듭니다.

```bash
python -c "import hashlib,getpass;print(hashlib.sha256(getpass.getpass().encode()).hexdigest())"
```

- **비밀번호는 저장소에 절대 들어가지 않습니다.** Secrets 에만 둡니다.
- **설정을 안 하면 앱이 열리지 않고 막힙니다.** 깜빡했을 때 공개되는 쪽이 더 위험해서
  일부러 그렇게 했습니다.
- 통과 전에는 저장된 내용을 불러오지도, 본문을 그리지도 않습니다.
- 통과 여부는 그 브라우저 세션에만 남습니다. 새로고침하면 다시 물어봅니다.
  (브라우저에 남기면 그 값을 흉내 내 우회할 수 있어 일부러 안 남깁니다.)
- 내 PC 에서는 `data/.local` 이 있으면 묻지 않습니다.

비밀번호는 **한 사람씩 따로가 아니라 모두가 같은 값**을 씁니다. 사람별로 나누고 싶으면
Streamlit Cloud 의 앱 설정에서 이메일 초대 방식(Viewer allowlist)을 쓰는 편이 낫습니다.

이 앱은 **사용자 데이터를 서버에 남기지 않습니다.**

| 항목 | 어디에 있나 |
|---|---|
| 입력한 이력 | 접속자의 브라우저(localStorage). 서버 저장 없음 |
| 올린 이력서 파일 | 메모리에서 읽고 버림. 디스크에 안 씀 |
| 만들어진 HTML·PPTX | 브라우저로 바로 내려감. 서버에 안 남음 |
| 다른 접속자 | 서로 아무것도 못 봄 (브라우저별 분리) |

서버 파일 저장은 `data/.local` 이 있을 때만 켜지고, 그 파일은 `.gitignore` 에
있어 배포본에는 절대 따라가지 않습니다.

공고 링크를 가져올 때만 서버가 바깥으로 요청을 보냅니다. 이때 나가는 건
**사용자가 입력한 공고 주소뿐**이고, 이력 내용은 나가지 않습니다.

> 공용 PC 를 썼다면 `불러오기 · 저장 → 브라우저 저장 내용 지우기` 를 눌러 주세요.

`tools/privacy_check.py` 로 저장소에 개인정보가 섞였는지 검사할 수 있습니다.
`tools/selftest.py` 는 앱 전체가 정상인지 점검합니다. (`tools/` 는 저장소에서 제외됩니다.)
